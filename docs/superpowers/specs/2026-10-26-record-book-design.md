# Record book and local sample preview

User direction: build the previously discussed record book with references to the games, add per-game stats, and populate examples for the user to inspect on localhost. Keep the approved Clay styling, black/white sides, bare numbers, and existing scoring flow. No browser automation.

Approach: derive records directly from the existing ordered goal events. No migration or persisted aggregate records; corrections and deletions automatically change the winners. Use a ruled ledger in the rivalry, small notable-moment tags directly below the game score card, and links that select and shade the corresponding momentum window without shading timeline rows. The homepage stays lean. A separate Records page or new stored statistics tables would add navigation/schema complexity without helping this small group.

Records: longest consecutive scoring run; most points in an inclusive rolling 30-second window; quickest full win measured start to final goal; fastest three points (opponent goals allowed between); fastest response to the immediately previous opponent point; largest deficit overcome by the eventual winner; most lead changes ignoring ties. Quickest win excludes early finishes, live games, and games with goals recorded after an earlier winning score.

Per-game presentation (updated after local review): no separate highlights section, quickest-win tile, or goal-dot sequences. Only compact clickable tags for a run of at least five, a rolling 30-second burst of at least three, and an immediate response under three seconds. Quiet games render no tag container. The three-second cutoff is an implementation choice communicated to the user. Record-book rows retain score transitions but omit goal beads. All seven records remain available in the rivalry book, now below game history. Extra rivalry stats: win fractions after scoring first, reaching 9–9, and trailing by three or more. Counts are visible alongside percentages; draws count toward denominators. Records use scoreboard credit including opponent own goals. Timing reflects logged timestamps and includes breaks.

Earliest game holds an equal record; show how many other games match. Within one game, an equal candidate keeps the first encountered candidate. Records link with `?record=<kind>#momentum`; invalid/missing record types are ignored. Source-game IDs remain stable and all references are recomputed from current data.

Release: user approved the local visuals and requested removal of sample data and production rollout. Preview mode and runtime seed generators are removed. At startup, retire only the dedicated `table-talk-record-preview-v1` localStorage/sessionStorage keys and redirect active sample URLs to the homepage. Preserve all ordinary local and shared Supabase data. A new unconfigured local table starts empty. Rich game fixtures now live under `src/test/fixtures` and are imported only by tests, never by the app.

Validation: pure calculation edge cases, fixture validity, full-app record-link navigation/highlight tests, targeted preview cleanup and preservation tests, existing scoring/mutation flows, TypeScript production build, and CSS inspection. User handles real browser/phone visual verification.
